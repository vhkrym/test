# 采购订单供应商拒单风险分析

## 1. 项目背景

采购订单被供应商拒绝接单，可能导致采购延迟和额外协调成本。本项目基于给定的采购订单数据，分析供应商拒单的相关风险信号，并构建一个基于历史数据的规则预警方案。

按照题目给定的成本口径，每次供应商拒单对应约 75 元损失，每次提前标记缺货风险的预警成本约为 10 元。

## 2. 分析目标

- 检查采购订单数据质量并识别重复记录。
- 分析不同物料品类、采购部门、库存水平及同步时间差下的拒单情况。
- 使用时间顺序切分数据，避免通过测试集选择预警阈值。
- 在较新订单上验证预警规则，并估算理论成本与收益。

## 3. 数据处理

原始数据共 954 条记录。重复记录审计发现 45 个重复采购单编号，重复编号之间未发现字段冲突。

分析时以 `po_id` 为唯一采购单标识进行去重，保留原始 CSV 不变。

| 数据指标 | 数量 |
|---|---:|
| 原始记录数 | 954 |
| 去除的重复记录数 | 45 |
| 去重后采购单数 | 909 |
| 接单 | 766 |
| 拒单 | 101 |
| 未回传状态 | 42 |
| 已知履约结果订单 | 867 |
| 已知结果订单拒单率 | 11.65% |

拒单率以履约状态已知的订单为分母，未回传状态不计入拒单率计算。

## 4. 主要发现

### 4.1 物料品类

- 实验耗材拒单率最高，为 18.48%。
- 防静电防护具拒单率为 16.88%。
- 应急备件拒单率相对较低，为 5.88%。

### 4.2 采购部门

- 华南仓储中心拒单率为 14.04%。
- 西南营运中心拒单率为 13.53%。
- 总部行政部拒单率相对较低，为 7.69%。

### 4.3 库存水平

库存不超过 8 的分组拒单率为 15.60%，高于其他库存分组。整体上，较低库存与较高拒单率存在关联，但不同分组之间并非严格单调关系。

### 4.4 供应商同步时间差

同步时间差最高的一组拒单率为 31.48%，其余分组约为 4.08%–7.45%。

这说明同步时间差是值得进一步验证的风险信号，但分组统计只能说明相关性，不能直接证明因果关系。

## 5. 预警规则与回测方法

候选规则以供应商同步时间差为依据：

`sync_age_hours > 0.2`

即同步时间差超过 0.2 小时（12 分钟）时触发预警。

回测按照订单时间排序，将较早的 606 单用于规则选择，将较新的 261 单作为测试集。阈值通过训练集选择，测试集用于评估规则在较新订单上的表现。

### 测试集结果

| 指标 | 结果 |
|---|---:|
| 测试集订单数 | 261 |
| 测试集拒单数 | 28 |
| 预警次数 | 67 |
| 命中拒单 | 18 |
| 误报 | 49 |
| 漏报拒单 | 10 |
| Precision | 26.87% |
| Recall | 64.29% |

Precision 表示预警订单中最终拒单的比例；Recall 表示实际拒单中被预警命中的比例。

### 理论成本收益估算

| 指标 | 结果 |
|---|---:|
| 命中拒单对应的理论可避免损失 | ¥1,350 |
| 预警成本 | ¥670 |
| 理论净收益 | ¥680 |
| 不预警基线理论净收益 | ¥0 |

上述估算假设每次命中拒单都能被成功避免，尚未经过真实业务干预验证。以测试集为例，预警干预成功率需要达到约 49.63%，才能覆盖预警成本。

## 6. 局限性与后续工作

- 当前分析基于单份历史数据，不能保证未来业务中的风险水平保持不变。
- 规则使用的是历史数据中的相关性信号，不代表已建立经过校准的拒单概率模型。
- 误报数量为 49 次，需要评估采购人员的处理能力及预警疲劳问题。
- 理论净收益依赖实际干预成功率，需通过小规模业务试点验证。
- 后续可增加滚动时间窗口回测、分组稳定性分析和预警阈值敏感性分析。

## 7. 项目文件

- `analyze.py`：数据清洗与描述性分析。
- `audit_duplicates.py`：重复采购单审计。
- `backtest.py`：时间顺序切分与规则回测。
- `results/summary.json`：总体统计结果。
- `results/backtest.json`：回测结果。
- `AI_LOG.md`：AI 辅助开发与验证记录。

## 8. 运行方式

在项目根目录放置题目提供的 `purchase_orders.csv`，安装 Python 及 pandas 后运行：

```bash
python audit_duplicates.py
python analyze.py
python backtest.py
```
